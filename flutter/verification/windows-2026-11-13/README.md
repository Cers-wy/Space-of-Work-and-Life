## 修复

1. `SpaceRepository.unpackBackup` 原先未关闭 ZIP 输入流，输出流的异步关闭也未等待。改为 finally 同步关闭，防止 Windows 备份包被持续占用。现有完整恢复用例新增“解包后立即重命名原包”断言，验证句柄释放。
2. Git 在 Windows 自动将逐字节比较的 portable JSON 夹具转为 CRLF。为这一个夹具设置 LF 属性，保持原始互操作字节；未修改业务序列化规则。
3. 两组组件测试在模拟时钟中关闭预览，未等待真实文件读取结束。改为等待预览加载状态结束，保留原交互断言；不修改产品 UI。删除重试方案经验证无效，未保留。
4. Flutter 测试进程原生崩溃已捕获本地转储。故障指令与同版本 flutter_windows.dll 的唯一指令序列及 PDB 符号匹配到 `dart::ProfilerNativeStackWalker::walk`。本机测试运行器关闭 Windows 测试命令的 Dart 栈采样后，PDF 原生与其余测试通过。属于本机工具链规避，不是产品崩溃修复证明，也不改变生产构建。转储含进程内存，只保留本地，不上传 Git。

## 复现

1. 使用锁定 Flutter 3.47.9，按现有 Windows CI 安装 C++ 桌面工具链，启用 Windows 开发人员模式。
2. 从 flutter 目录恢复锁定依赖与四个固定 OCR 模型。GitHub 访问需按本机实际网络设置代理；不要照搬别人的端口。
3. 执行 `tool/test_windows_baseline.ps1`；可用 `-TestFiles` 指定后续受影响测试。脚本把临时数据隔离到项目 work/，并调用 configure_windows_tests.ps1 应用已解释的版本限定测试采样规避。规避会重建本地 Flutter 工具快照，首次需要依赖可用；换 Flutter 版本须重新评估，脚本会拒绝直接套用。
4. 测试脚本仅对其进程和子进程设置错误弹窗模式。原生崩溃仍返回失败并保留日志，不改系统安全设置，不把崩溃记为通过。
5. `tool/core_performance.dart`、`tool/windows_core_performance.dart` 用 Flutter Release 打包原生资产，只作探针；设置项目内空的 SPACE_FLUTTER_DATA_DIRECTORY，后者还需 SPACE_PROBE_FONT 指向有中文字符的本机 TTF。测完重建 `lib/main.dart`，禁止交付探针入口。

## 性能口径与未完成项

- core-1000.json / core-10000.json：Flutter Release AOT 后台核心操作；查询和读校验各 30 次、保存 10 次、加解密 1 次。不包含前台帧耗时。
- native-performance.json：合成发票、100 页裁边与合并三轮、小/中 OCR 三轮及工作线程释放后空闲。冷启动和重复调用分开列出。CPU 为单逻辑核 100% 口径，16 线程机器全机百分比约除以 16；短操作的前后进程快照存在采样开销，不用于精确 CPU 结论。RSS 是进程工作集，峰值是进程累计峰值，不等于单场景独占峰值或长期泄漏证明。
- 初步采样与构建/测试有交叉，仅用于排障；最终核心采样在停止本轮编译与测试后串行执行。native-performance-initial.json 为初步记录，不作为最终性能结论。
- 首次前台探针等待焦点失败，未执行有效场景；电脑控制工具返回“Computer Use was not approved to use Space”。此次结果无效。需要允许工具访问测试 Space 或用户手动保持其前台后重跑。尚无可用前台帧耗时、掉帧率或鼠标手工体验证据。
- 实体打印、扫码、真实网盘联调、长期运行泄漏、其他 Windows 硬件均未验证。不得据本记录宣称这些项目通过。

## 程序更新包与数据保护

交付 ZIP 仅含运行所需 EXE、DLL、模型、资源及第三方许可。native_assets.json 是运行所需原生库清单，不是个人配置。包内不含数据库、备份、网盘连接、令牌、个人设置或测试资料。生产默认数据位于 `%APPDATA%\SpaceFlutter`，与程序目录分开。关闭旧程序后覆盖程序文件，保留现有个人目录；本轮不替用户执行覆盖更新。
