## 1.5.0 GitHub私有仓库加密同步

- 基于1.4.0 build8继续开发，保留性能优化、过渡动画、甘特图项目层级与拖拽编辑。
- “数据与设置”新增GitHub同步。默认账号18390208101、仓库space-sync-data、main分支、backups/latest.space。仅允许私有仓库，先校验仓库、分支及访问权限。
- 任务数据从SQLite Backup API取得一致快照后，转换为加密的逻辑数据库备份；保留任务、项目、状态顺序/启停、开始与截止日期及附件。界面偏好、同步地址、凭据不上传，恢复时保留本机设置。
- GitHub Token与随机256位恢复密钥存入macOS钥匙串，不写入SQLite、备份或日志。另一台Mac需配置自己的Token和相同恢复密钥；请将恢复密钥另外保存在密码管理器，丢失后无法解密。
- 手动检查并同步、下载预览与备份恢复，以及明确确认后用本机覆盖云端。文件SHA校验更新，比较上次同步内容指纹；两端同时变化或云端备份被删除时暂停自动覆盖。
- 可选自动同步：首次手动连接建立基线后，修改停止30秒、应用重新激活、每5分钟检查时执行。无变化不提交；网络失败逐步退避，限流暂停15分钟。完全退出软件后不运行，不新增常驻后台服务。
- 首次连接、手动恢复与强制覆盖需明确确认。恢复前自动保留上一份SQLite快照；下载期间本地变化会阻止恢复。自动恢复仅发生在本地内容未偏离同步基线且没有打开任务编辑器时。
- GitHub备份是SPACE-GITHUB-1加密包，不是可直接用SQLite工具打开的文件。加密包上限24MB；不自动合并两端同时修改，不在第一版提供历史版本选择界面。GitHub提交历史保留旧备份，后续可实现选择历史恢复。

配置步骤：

1. 创建私有仓库并初始化main分支。本项目仓库已建立：https://github.com/18390208101/space-sync-data 。
2. 在GitHub创建细粒度Token：仅选space-sync-data，Contents设为Read and write，建议90天有效期。直接粘贴进Space，不在聊天、源码或仓库中保存。
3. 第一台Mac点击“生成恢复密钥”，点击“保存GitHub配置”，再复制已存密钥到密码管理器。其他设备填写同一恢复密钥，不能重新生成覆盖原密钥。
4. 点击“检查并同步”并确认首次上传。第二台Mac使用相同仓库、路径和密钥，点击检查后预览并确认恢复。
5. 按需开启自动同步并保存配置。两端都有修改时，先导出本地SQLite备份，再决定恢复云端或明确上传本机；第一版不自动合并。

### 配置同步

1. 在两台Mac上使用Space 1.2.0或兼容版本；打开“数据与设置”。
2. 填写双方都能访问的同一HTTPS/WebDAV目录（需预先存在，支持PUT/GET），或选择已挂载的NAS共享文件夹。直接对象存储需提供兼容HTTP读写的网关；目前不支持S3签名、OAuth或交互式网页登录。
3. 若服务需要Basic认证，填写用户名和密码并保存。地址与用户名写入SQLite；密码仅写入本机钥匙串，备份不会携带密码。另一设备单独配置访问凭据。
4. 来源设备点击“上传数据库备份”，将生成的完整SP验证码交给目标设备。目标设备输入验证码，点击“下载并校验”，查看任务、项目和状态数量。
5. “备份并合并”保留双方任务，同ID任务采用修改时间较新的一份；相同时间但内容冲突会阻止合并，需要明确选择整库替换。合并不传播删除，旧快照中的任务可能被重新加入。“备份并替换”以下载快照为准。两者均先保留本地上一份数据库，且保留本机同步地址。

这是用户主动执行的快照同步，不进行后台实时同步。验证码包含随机128位密钥材料，快照采用AES-GCM加密并校验摘要，文件名由验证码哈希生成。验证码需连同正确的网络目录使用；7天后应用拒绝下载导入，服务器上的加密文件不会自动删除。上传时数据库上限32MB，加密包上限64MB。同步期间本地版本变化会阻止导入；已应用的验证码不会重复应用。

### 备份格式

默认导出独立SQLite快照，通过SQLite Backup API取得一致内容，包含已提交的WAL数据，可直接导入，不需手工复制正在使用的数据库文件。也可导出JSON；新版兼容ORBIT V1、Space V2、含项目、启停、设置的Space V3、含图片附件的Space V4及含开始日期的Space V5。旧版软件不能读取新版V3/V4或SQLite，降级前请保留旧JSON和旧应用。

## 数据位置与恢复

正式数据库：

```text
~/Library/Application Support/com.cers.orbit/space.sqlite
~/Library/Application Support/com.cers.orbit/space.previous.sqlite
```

SQLite使用事务、外键、完整性校验和版本冲突检测。写入前保留上一份快照；读取失败不会自动清空原库。设置中可恢复上次备份或导入其他有效SQLite/JSON。长期备份请使用“导出SQLite”。SQLite备份导入上限64MB；JSON为64MB与最多10,000项任务。

首次迁移保留 `tasks.json` 与 `tasks.before-sqlite.json`；旧版的 `tasks.previous.json` 同样不删除。旧JSON是迁移来源和历史备份，升级后的修改以SQLite为准。界面设置也写入SQLite，本机同步密码保存在钥匙串。

应用重启会保留已保存任务；撤销仅覆盖本次运行最近一次任务更改。外部进程修改主文件后，本应用会阻止使用旧版本覆盖并提示重新载入；若编辑面板有未保存内容，应先复制或处理该内容再重新载入。

所有任务日期按 `Asia/Shanghai` 处理。无日期不判为逾期；已完成任务不进入今天与逾期入口；重新开启默认回到待办并清除完成时间。标题最多100个UTF-16单位、说明最多5,000个，与原HTML版校验口径一致；单次JSON备份不超过64MB，最多10,000项任务。

## 从 HTML 演示版迁移

1. 在原演示版“数据与设置”中导出 JSON。
2. 打开原生应用“数据与设置”→“导入备份”。
3. 检查任务数量并确认替换。原生版保存成功后，再核对任务。

原 HTML、浏览器 localStorage 和既有方案文件保持不变。原生应用不会自动读取浏览器私有存储。

## 开发与构建

需要 Xcode 或带 macOS SDK 的 Swift 工具链。可以在 Xcode 中打开 `native/Package.swift` 阅读和调试。

在项目根目录执行：

```sh
zsh native/scripts/test.sh
zsh native/scripts/build-app.sh
open output/Space.app
```

脚本将编译产物与缓存放在工作区 `work/`，输出应用至 `output/Space.app`，并校验本机临时签名。构建脚本使用 `--disable-sandbox` 关闭 SwiftPM 构建过程的嵌套沙箱；不修改应用权限或系统安全设置。

```text
native/
  Package.swift
  Sources/OrbitCore/       数据模型、查询、验证、SQLite持久化与加密同步
  Sources/OrbitApp/        SwiftUI界面、AppKit集成、应用状态
  Tests/OrbitCoreTests/    业务与数据可靠性测试
  Resources/              应用信息与图标
  scripts/                测试、构建及矢量绘制图标脚本
```
