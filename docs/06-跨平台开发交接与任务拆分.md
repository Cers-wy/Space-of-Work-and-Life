# 跨平台开发交接与任务拆分

## 1. 交接目的与基准

在另一台电脑上复刻 Space 桌面应用，行为与界面基准均为本仓库 `native/` 的 macOS 1.6.0 build10。先阅读 [00](00-阅读指南与复刻基线.md) 和 [01](01-完整功能需求PRD.md)，再按本文件实施。后来的 WPF/Avalonia 实验不是被用户接受的最终视觉基准，不能拿其通过的业务检查替代原版比对。

用户尚未指定本次复刻目标系统和技术栈。可按目标平台选择原生框架或成熟跨平台桌面框架，但必须保留轻量、低空闲开销、精细 UI 和完整数据保护目标；不要直接把已有 SwiftUI 代码包成 WebView 就声称完成其他平台版。若选择浏览器运行时方案，应先说明新增运行依赖与资源成本并取得技术路线决定。

## 2. 在另一台电脑取得资料

以能访问私有仓库的本人 GitHub 账号登录后 clone 或下载 ZIP；仓库不附带 Token 或恢复密钥。

```sh
git clone https://github.com/18390208101/Space-macOS-native.git
```

原生源码固定提交 `1b07c70dbfdddbb8fb3393937badce91ed6413aa`；后续提交增加 docs/history/fixtures，原生 45 个文件不应变化。用 SOURCE-MANIFEST 逐文件核对后再开始。

macOS 可从根目录运行 `zsh native/scripts/test.sh`、`zsh native/scripts/build-app.sh`，构建 `output/Space.app`。其他平台不能直接编译 SwiftUI/AppKit；将原实现视为行为和视觉参考，业务规则/协议另行实现。

## 3. 模块边界与建议接口

下面是移植组织建议，不是原版新增的功能/API 承诺。

| 模块 | 职责 | 禁止混入 |
|---|---|---|
| Domain | Task、Status、Project、Attachment、Date、Query、Schedule | UI 组件、凭据存储 |
| Repository | SQLite、事务、快照、revision、迁移、完整校验 | 自动确认覆盖、格式降级 |
| Application State | 草稿、查询、缓存、单步撤销、提交与错误消息 | 每帧拖指针全局发布 |
| Presentation | 四视图、表单、主题与统一控件 | 另存一份互不一致的任务库 |
| Rich Text Adapter | 文本镜像、格式、图、RTFD 互通 | 无提示丢掉原始富文本 |
| Sync Codec | portable、指纹、AES-GCM、SP 信封 | HTTP、UI 弹窗、真实凭据 |
| Sync Transport | GitHub/HTTPS/本地目录 | 凭据打印、绕过 SHA 保护 |
| Secure Store | 系统凭据保险库 | 明文 JSON/配置备份 |
| Packaging | 架构、版本、安装/升级、许可证 | 用户真实数据库和测试密钥混用 |

建议可测试操作：validateTask、applyQuery、resolveSchedule、changeStatus、saveTask、savePreferences、exportSnapshot、readBackup、seal/unseal、resolveSyncDecision。UI 必须调用同一业务入口，不能让看板拖动与详情保存各写一套完成时间逻辑。

## 4. 分阶段任务与完成条件

| 阶段 | 工作项 | 交付物 | 进入下一阶段的条件 |
|---|---|---|---|
| A 基线与选型 | 固定版本、核对 manifest、目标系统/架构/字体/RTFD 方案 | 技术路线和差异表、最小可运行窗口 | 明亮/暗色控件样板、玻璃层次、资源预算可评估 |
| B 领域与数据 | 字段校验、日期、状态、查询/排序、排期、SQLite/迁移/备份 | 单元测试、空库、旧 JSON 导入导出 | 主 PRD 数据边界通过，失败不覆盖 |
| C 主界面与任务 | 导航/概览、分类、看板/列表、表单、项目/状态、撤销 | 可操作版本、四种主要弹窗 | 增改删重启、键盘、停用/迁移删除通过 |
| D 图文附件 | 富文本、真实剪贴板、限制、预览/另存、RTFD 双向 | 合成富文本往返文件和截图 | Mac→目标→Mac 能保留格式和图片；否则明示不完整 |
| E 排期 | 甘特项目层级、裁剪与拖动、日历日周月/更多 | 跨月/跨年/闰年及拖动验收 | 每次拖动只保存一次，默认日期不落库 |
| F 同步 | 先 codec 后传输；安全存储、GitHub 状态机、SP 合并 | 测试仓库与两隔离数据库记录 | 错钥匙/篡改/双边冲突/删除远端均保护成功 |
| G UI 与资源 | 多尺寸/DPI、滚动、图标、材质、焦点、减少动态效果 | 与原版同条件对照截图、资源采样 | 功能通过与视觉通过分别确认 |
| H 打包交付 | 目标架构可安装包、版本、升级、卸载说明 | 可运行安装产物、SHA256、使用说明 | 目标系统干净环境实测，保留数据且不依赖开发机 |

不要在第一轮就把所有页面用框架默认控件拼完后宣称一比一。先做主题、玻璃、按钮、下拉、日期、侧栏轮廓的小样，在原版同尺寸下校对，再复用到各页。

## 5. 平台能力替代

| macOS 能力 | 移植要求 | 可接受的适配说明 |
|---|---|---|
| SwiftUI/AppKit | 目标系统可运行桌面实现 | 组件实现不同，业务与布局需相同验收 |
| ultraThinMaterial | 保留背景柔光、半透明叠层、亮边和层次 | 系统材质不可同像素时列出差异；不能退化硬边块 |
| PingFang SC | 合规安装/使用，或提供中文替代字体 | 记录字重/行高/宽度差异，不打包未经授权字体 |
| SF Symbols | 采用合规矢量等价图形 | 对照光学尺寸、描边与语义，不只对照名称 |
| flat RTFD | 正确读取、显示、编辑和回写 | 只读携带/单向转换不能算完整复刻 |
| Keychain | 系统安全存储 | 设备迁移需本人另行配置，凭据不进代码 |
| Quick Look | 图片/PDF/文本预览或系统关联预览 | 不支持的类型明确提供另存后打开 |
| NSOpen/SavePanel | 系统原生文件对话框 | 中文可读、取消无修改、权限错误反馈 |
| flock + SQLite Backup | 系统进程锁 + 一致快照 | 需要包含 WAL，失败可回滚 |
| Command 快捷键 | Ctrl/平台主修饰键 | 帮助显示实际快捷键，输入法期间不劫持 |

## 6. 数据与运行隔离

开发/自动化使用独立应用 ID 和目录，不自动读取正式 com.cers.orbit、钥匙串或 GitHub 配置。合成 fixtures 中所有任务都标记为示例，测试密钥只用于互通向量。真实同步验证创建专用私有测试仓库/路径，不覆盖 `space-sync-data/backups/latest.space`。

其他平台目录采用其用户级应用数据规范，设置中显示实际位置。安装/升级只替换程序，保留用户数据；卸载是否删除数据必须由明确动作决定。不要将数据库放在应用安装目录导致升级覆盖或普通用户无写权限。

## 7. 性能验收和记录方法

原版曾在特定 Mac、120 任务、10 秒静止采样中观察到 CPU 中位数约 0.25%、RSS 113.1 MiB；这是 1.4.0 历史条件数据，不是跨平台硬指标或长期保证。新实现先记录空库、常见规模、1000 任务的冷启动、空闲、悬停、拖动、视图切换和带附件保存；注明设备、系统、架构、缩放、窗口、数据量、采样时长及测量工具。

必须避免的回归：所有任务卡永久高帧率动画；指针位置每次变动触发全库重算；主题切换重写附件；每 30 秒即重绘全工作台；下载恢复形成自动上传循环。不能把采图工具带来的占用作为日常空闲占用，也不能只取最低瞬间值。

## 8. 发布前交付清单

- 源码固定提交、构建命令、所需 SDK/运行库和自包含情况。
- 目标平台真实运行的安装/便携产物、架构、版本、SHA256。
- [05](05-验收用例.md) 每条通过/失败/未测、测试环境与证据路径。
- 亮暗主题四视图与各弹窗截图，1020/1180/1380/1600 宽及常用 DPI 的实际检查。
- 真实键盘、输入法、拖动、文件选择、剪贴板图片、预览和重启验证。
- Mac 与目标系统往返的 JSON/SQLite/图文/同步样本；两边任务数量、字段、附件哈希、项目顺序及完成时间比对。
- 已知差异与待验证事项，尤其 RTFD、字体、系统材质、双设备冲突，不用“已完成”掩盖。

## 9. 可直接交给另一台电脑的工作指令

> 请基于本仓库 docs/00～07 和 native/，在我指定的目标操作系统复刻 Space。唯一产品与视觉基准是 macOS 原生 1.6.0 build10，源码提交 1b07c70dbfdddbb8fb3393937badce91ed6413aa。先核对 SOURCE-MANIFEST，然后提出适合目标系统且空闲资源开销低的技术路线，明确字体、系统玻璃、文件预览、安全存储、RTFD 兼容方案。分阶段实现，不修改 native/ 原始基线；测试使用隔离目录和合成 fixtures。业务逻辑必须统一，导入/恢复/同步要完整校验、先备份、事务写入、版本与 SHA 冲突停止。每阶段运行对应验收，功能与视觉分别给证据。不要直接采用此前 WPF/Avalonia 实验的外观作为基准，不因自动测试通过就声称一比一完成。交付目标系统真实可运行的安装产物、构建说明、截图、测试结果和已知差异。

## 10. 差异待决事项

目标系统/CPU/最低版本、技术框架、字体替代、RTFD 双向编辑方案、系统预览能力、系统玻璃差异、是否改善顶部分类新建默认值、是否联动删除内嵌图与原附件，均需在实际移植阶段作出明确选择。除此之外按当前需求执行，不重复询问已经由固定源码确定的字段与规则。
