# Space 跨平台复刻资料包

基准软件：macOS 原生 Space **1.6.0 build10**。整理日期：2026-11-02（北京时间）。

本资料包面向在另一台电脑上重新实现 Windows、Linux 或其他平台桌面版的开发者。需求依据原生 SwiftUI / AppKit 代码、自动化测试和历史验收记录整理；无需读取本机个人任务库即可开展开发。

## 一、先固定基线

- GitHub 私有仓库：<https://github.com/18390208101/Space-macOS-native>。
- 原生源码备份提交：`1b07c70dbfdddbb8fb3393937badce91ed6413aa`。
- 原生源码目录：[`native/`](../native/)。45 个源码、测试、资源和构建文件的 SHA-256 见 [`SOURCE-MANIFEST.json`](../SOURCE-MANIFEST.json)。
- 本次上传的是原生 1.6.0 build10。旧 Windows WPF 版、Avalonia build13 / build14 验证版都不是本资料包的行为与视觉基线。
- 源码备份不包含正式 SQLite 数据库、用户附件、访问令牌、恢复密钥或本机连接记录。另一台电脑首次运行应为空工作台。

## 三、证据与要求的含义

1. **当前行为**：可在固定提交源码或已有测试中定位。涉及平台行为时，不把代码存在等同于所有系统端到端验证完成。
2. **复刻要求**：移植后必须达到的用户可见行为及数据保护条件；通常直接继承当前行为。
3. **移植建议**：实现路线或合理替代方案，不冒充已经开发的能力。
4. **差异待决**：历史说明与源码不一致、或存在技术局限的项目；必须显式记录选择，不能悄悄把数据丢失当作兼容。

发生冲突时，先核对固定版本实际代码和最新 1.6.0 验收，不能拿 1.2/1.3 历史说明覆盖最新版。历史材料完整保留在 [`history/`](../history/) 中，历史的测试通过数量、用户任务数量和旧版本界面不代表当前版本的新承诺。

## 四、复刻边界

必须覆盖四视图、任务/项目/状态、富文本与附件、持久化/恢复、两套同步和对应错误保护。目标平台尚未指定，因此本资料不强制选择某个 UI 框架，也不承诺苹果系统材质、字体与系统窗口外壳在另一系统天然一致。

本版没有团队账号、审批、小时级日程、重复任务、提醒推送、依赖连线、子任务、系统日历集成、自动多方合并或退出应用后的后台同步。若要增加，需另立增量需求，不应混入原生版复刻验收。

## 五、本次验证
