# 同步与加密实现要求

本文定义两套同步的用户流程、连接字段、冲突处理、数据范围和加密格式。实现位置为 `GitHubDatabaseSync.swift`、`GitHubSyncController.swift`、`DatabaseSync.swift`。

## 1. 两条同步路线的差异

| 维度 | GitHub 私有仓库 | 其他位置手动快照 |
|---|---|---|
| 载荷 | 任务逻辑备份 JSON，过滤设备偏好 | 完整 SQLite 快照 |
| 目标 | api.github.com 对应私有仓库文件 | HTTPS/WebDAV PUT/GET 或已挂载目录 |
| 密钥 | 固定随机 256 位恢复密钥 | 从本次随机 128 位 SP 码派生 |
| 时效 | 没有 7 天期限 | 上传后 7 天 |
| 自动触发 | 可选，必须先手动建立基线 | 无 |
| 冲突 | 两边同时改即暂停，不合并 | 用户选择合并或替换 |
| 删除传播 | 整库恢复体现删除 | 合并保留并集，不传播删除 |
| 本机外观 | 不上传、不恢复 | 快照携带，应用时覆盖允许的设置 |
| 凭据 | Token 与恢复密钥在安全存储 | 访问密码在安全存储 |
| 限额 | 加密包 <=24 MiB | 原库 <=32 MiB，下载信封 <=64 MiB |

两套同步互斥执行。不能把“手动快照可合并”的策略复制给 GitHub 自动同步，或把 SP 码当作 GitHub 恢复密钥。

## 2. GitHub 配置与安全存储

字段 owner/repository 限 1～100 UTF-8 字节，只允许 ASCII 字母、数字、`-_.`，不能是 `.`/`..`；branch 非空 <=255 UTF-8，不含空白/控制字符；path 非空 <=512 UTF-8，`/` 分段每段非空、<=100 字节、不能 `.`/`..`，不可含反斜杠和控制字符。

连接身份：

```text
identity = lowercaseHex(SHA256(UTF8(
    lowercase(owner) + "/" + lowercase(repository) + "\n" + branch + "\n" + path
)))
```

账号/仓库大小写规范化，分支与路径大小写保留。改变 identity 必须清空旧同步基线；更换恢复密钥也清空 baseSHA/baseFingerprint/lastSyncedAt，防止新密钥静默覆盖旧云端。

原版钥匙串 service=`com.cers.space.github`，account=`identity:token` 或 `identity:key`，设备本地保护；自动读取不弹交互授权。目标平台使用系统凭据保险库等价机制，严禁放入 SQLite、源码、日志、云端或文档。手动位置密码独立 service=`com.cers.space.sync`，账户键是 SHA256(location+换行+username)。

非敏感 `github-sync.json` 包含 configuration、automatic、baseSHA、baseFingerprint、lastSyncedAt；读取上限 16 KiB、原子写、权限 0600。Token/key 输入留空保留；保存成功清空输入显示。复制密钥是用户主动操作；不能以 debug 日志回显。

## 3. GitHub portable 与内容指纹

构造新 TaskBackup：

1. tasks 按 ID 升序；完整保留任务、富文本、附件和日期。
2. statuses 保留顺序；projects 保留顺序；disabledStatuses 按 rawValue 升序。
3. 不传入 settings、workspaceID、revision，使设备外观/连接/修订号不参与。
4. now 固定 `1970-01-01T00:00:00.000Z`，避免每次导出时间不同造成变更。
5. 按 TaskBackup 内容选择 V1～V6，再使用 JSONEncoder prettyPrinted + sortedKeys + withoutEscapingSlashes 编码。
6. `fingerprint = SHA256(上述实际 UTF-8 字节)`，输出小写十六进制。

不能仅把同一 JSON 对象交给任意 serializer 后就认为指纹一样：缩进、换行、键序、斜杠转义、Unicode、可选字段、Base64 和时间戳写法均可能影响字节。跨平台若要共用基线指纹，必须对照原生输出字节；如使用语义指纹的新算法，应设计独立版本与迁移，不能沿用旧字段假装相同。

仅改变本机主题或 revision 不应触发 GitHub 上传。删除任务、修改附件/富文本/日期、项目顺序或状态启停应改变 portable 和指纹。每次 AES-GCM 加密 nonce 随机，密文变不等于业务变更，不能用密文哈希作为本地业务指纹。

## 4. GitHub 加密包

```text
header = UTF8("SPACE-GITHUB-1\n")
key = Base64Decode(trim(recoveryKey))  // 必须恰好 32 字节
plaintext = portable TaskBackup 的编码字节
sealed = AES-256-GCM(plaintext, key, randomNonce, AAD=header)
packet = header || nonce[12] || ciphertext[n] || authenticationTag[16]
```

该组合顺序对应 CryptoKit `AES.GCM.SealedBox.combined`，不是有些库返回的 ciphertext||tag||nonce。packet 总长度 <=24×1024²。解密必须检查 header、长度、GCM 标签和 TaskBackup 全部业务字段，任一失败不修改本地。

恢复密钥为标准 Base64 文本的 32 字节随机数，不是密码、Token 或从账号推导。协议没有密码 KDF，不可自作主张在另一端额外 SHA256 密钥字符串。富文本与附件存在 JSON Base64 膨胀且可能重复存图，更容易达到上限。

## 5. GitHub 请求约束

主机固定 HTTPS `api.github.com`，组件分别 percent encode。原生请求超时 45 秒、ephemeral session、拒绝重定向；携 Token 的请求不能跳转到其他域名。请求头使用 Bearer token、API version `2022-11-28`、User-Agent Space-macOS（移植可保留或标注新客户端），请求 JSON 时 Content-Type application/json。

| 操作 | 路径/方法 | 核验 |
|---|---|---|
| 验证仓库 | GET /repos/{owner}/{repo} | private 必须 true |
| 验证分支 | GET /repos/{owner}/{repo}/branches/{branch} | 存在且有权限 |
| 文件元数据 | GET contents/{path}?ref={branch} | size 在限额内，SHA 40 个十六进制字符 |
| 大文件原始 blob | GET git/blobs/{sha}，raw Accept | 固定先前 SHA，不重新按路径取最新版 |
| 创建/更新 | PUT contents/{path} | body message/content(Base64)/branch，更新带期望 sha，创建省略 |

只有仓库与分支先验证通过后，备份文件的 404 才可按“尚无备份”解释；否则可能是未授权，不能直接首次覆盖。

读取内嵌 Base64 时校验实际内容长度和 Git blob SHA；没有内嵌内容时按确切 blob SHA 下载。Git 对象哈希：

```text
blobSHA = lowercaseHex(SHA1(UTF8("blob " + decimalByteLength + "\0") || packet))
```

SHA1 在此用于 Git 协议对象寻址，完整性/认证仍由 GCM 与载荷校验负责。PUT 成功回包的 content.sha 必须等于客户端计算值；409/422 不得自动取最新 SHA 后强制重试。

## 6. GitHub 决策表

变量：L=当前 portable 指纹；Bf=上次成功基线指纹；R=远端文件 SHA；Bs=上次成功远端 SHA。

| 条件 | decision | 自动行为/手动结果 |
|---|---|---|
| 无 R、无 Bs | initialize | 必须手动确认首次上传；自动不初始化 |
| 无 R、有 Bs | conflict | 云端被删除，停止覆盖 |
| 有 R、无完整 Bs/Bf | connect | 下载解密；相同建立基线，不同预览恢复 |
| L=Bf 且 R=Bs | unchanged | 不提交，无变化提示 |
| L!=Bf 且 R=Bs | upload | 校验既有密钥可解远端，再带 SHA 上传 |
| L=Bf 且 R!=Bs | download | 下载；自动满足保护条件可恢复，否则预览 |
| L!=Bf 且 R!=Bs | conflict | 停止，让用户明确选择 |

`downloadOnly` 强制进入下载路径；`overwrite` 强制上传，但仍要求明确确认、既有包能用当前密钥解密、带期望 SHA。强制覆盖不是绕过权限、错误密钥或并发保护。

## 7. GitHub 上传/恢复生命周期

上传前先验证远端，再使用 SQLite Backup API 取得一致快照并读取逻辑状态，避免请求等待期间本地变化导致旧快照被当作最新。上传期间若本地又修改，记录本次上传对应的基线指纹并提示仍有待同步；安排下一次检查，不能把新本地内容错误标为已上传。

下载解密前记录本地指纹；网络完成后再次对比。正在任务编辑/另一同步时拒绝恢复；预览后应用前也再次核对。恢复先备份本地，再提交完整业务状态，保留本机 settings；成功后更新 Bs、Bf、lastSyncedAt，清除 pending。取消或失败保持原库。

只有单边远端变化、自动已开、已建立基线、本地指纹仍等于基线且没有任务编辑时，自动恢复才允许。存在 pending 预览时自动检查暂停，避免用户还在决定时数据被换掉。

## 8. 自动触发与退避

- automatic 缺省 false；首次手动成功建立 baseline 后才可自动执行。
- 本地成功业务变化后 30 秒防抖；每 300 秒；应用重新激活；启动时条件允许则检查。
- 后续操作重置防抖；恢复应用过程中用 applying 标志避免自身恢复立即形成上传循环。
- 空闲无变化不提交；退出后无后台进程或定时服务。
- 失败等待 60、120、240、480、900 秒，后续 900；限流直接 900 秒。
- 原生 synchronize 的 nextAttempt 也限制手动按钮，不能承诺手动总能立即绕过退避。

| 错误 | 分类/反馈 |
|---|---|
| 401 | Token 无效/过期，重新配置 |
| 403 非限流 | 权限/组织授权不足 |
| 403 且 remaining=0 或 Retry-After、429 | 限流，暂停 15 分钟 |
| 404 | 仓库/分支不存在或未授权；文件缺失仅在验证目标后单独解释 |
| 409 / 422 | 云端改变，停止覆盖 |
| 内容/哈希/解密/版本无效 | 拒绝导入，保留本地 |
| 其他 HTTP/断网 | 可读失败，不回显响应体或凭据 |

## 9. SP 手动同步报文

### 9.1 目标与传输

地址可为绝对文件夹路径、file URL、或无 URL 凭据/查询/fragment 的 HTTPS 目录。HTTP 不支持；SMB/NAS 应先挂载成文件夹，不把 SMB URL 当 HTTPS。支持 Basic 用户名/密码或免认证目录；当前没有 OAuth/S3 签名/网页授权适配。

HTTPS PUT 使用 application/octet-stream、If-None-Match:*，成功码 200/201/204；GET 必须 200。请求超时 45 秒，资源 90 秒，ephemeral、禁 cookies。通用 HTTPS 传输使用 URLSession 的重定向处理；GitHub 传输单独拒绝重定向。

### 9.2 验证码、文件名与密钥

```text
random = 16 个安全随机字节
hex = 32 位大写十六进制
code = "SP-" + 每 4 位用 '-' 分组（共 8 组）
clean = uppercase(code) 去所有空白与 '-'，再去可选前缀 SP
clean 必须为 32 个 0～9/A～F
receiptID = SHA256(UTF8(clean)) 的小写 hex
filename = "space-" + receiptID + ".spacesync"
key = SHA256(UTF8("Space encrypted SQLite backup v1:" + clean)) 的 32 字节
```

验证码本身带密钥材料，应按备份访问能力保护，不是低熵短信六位码。文件名不包含原码，不能通过文件名反推出解密密钥。

### 9.3 信封

外层 UTF-8 JSON：`{"format":1,"sealed":"Base64(nonce||ciphertext||tag)"}`。AES-256-GCM 使用上面派生的 key；这条协议没有 header AAD。

解密内层 JSON 字段：database（完整 SQLite 字节的 Base64）、digest（数据库 SHA256 小写 hex）、createdAt、expiresAt。

**日期兼容重点**：内层 createdAt/expiresAt 是 Swift Date 的默认 JSONEncoder 数值，即距 **2001-01-01T00:00:00Z** 的秒数，可有小数；不是 Unix 秒，也不是 ISO 字符串。Unix 秒 = 该值 +978307200。独立 github-sync.json 的 Date 字段也使用该默认策略；任务时间戳则仍为 ISO 字符串。

上传库字节 <=32 MiB；内层先编码再加密，外层再次 Base64，所以包大小有多次膨胀。下载外层 <=64 MiB、format=1；GCM 通过后要求 expiresAt>当前时间、createdAt<=当前时间+300 秒、库长度 <=32 MiB、digest 相等；再以 SQLite/业务校验读取。

有效期是上传 createdAt+7×86400 秒。过期后客户端拒读，服务器文件不会自动删除。`DownloadedSnapshot.expiresAt` 当前返回代码采用下载时 now+7 天，与密文原 expiresAt 不同；原版 UI 没有据此展示真实有效期，移植不要拿该返回字段延长真实过期时间。

## 10. 手动下载预览与合并

下载开始保存 revision；完成或应用前 revision 改变立即停止。已用 receipt 在 sync.lastReceipt 或最近 64 条历史中出现就提示无需重复。临时解密库读取结束后删除，不能留在公开临时路径。

合并步骤：

1. 两份逻辑状态均完整校验。
2. 项目先按名称大小写不敏感复用本地 ID，改写远端任务 projectID；同 ID 不同名拒绝，其他追加。
3. 按任务 ID 并集；内容相同直接保留；不同则解析 updatedAt，较新胜出；相同时间不同内容拒绝，要求备份后明确替换。
4. 任务最终按 ID 升序；状态沿用本地顺序，新增远端状态插在 done 前。
5. 已有状态的启停以本地为准；远端新增状态携带其停用信息。
6. 远端非 `sync.*` 设置覆盖对应键，本机 sync.* 保留；workspaceID 本机保留。
7. 用户确认后先备份、再原子提交；记录 receipt 并清 pending。

整库替换使用远端业务数据及允许的非 sync.* 设置，保留本机同步地址和应用身份。取消预览不修改数据库。并集没有删除墓碑，所以旧快照合并可能让已删除任务重新出现，必须在界面/帮助中清楚说明。

## 11. 必须分开的验证级别

1. 纯协议测试：错误密钥、篡改、哈希、日期、随机 nonce、格式版本、限制。
2. 本地两个隔离仓库：互导附件、富文本、项目顺序、开始日期、状态启停、偏好保留。
3. 模拟 GitHub API：私有/公开、404、旧 SHA、raw blob、限流/认证，不打印 Token。
4. 真实测试仓库：上传下载、自动检查、两台目标设备首连/恢复/双边冲突。
5. 平台 UI 实测：安全存储授权、系统文件夹、真实 PNG/TIFF/文件剪贴板和退出重开。

协议、界面和真实双设备同步分别验证。模拟 API 或本地数据库互导通过后，仍须在目标设备执行首次连接、自动检查、恢复与双边冲突测试。
