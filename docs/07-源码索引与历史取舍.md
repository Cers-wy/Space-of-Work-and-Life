## 2. 历史规则替代关系

| 历史材料 | 历史行为 | 当前1.6.0采用的规则 |
|---|---|---|
| 1.0/HTML原型 | ORBIT品牌、多侧栏分类入口、旧配色 | Space；只有任务入口；颜色按当前Appearance源码 |
| 1.0.2/fix2 | 黑灰亮紫、8pt、四周光边 | 保留颜色基底，但背景又有柔光叠层，不能理解成没有紫光 |
| 1.1/fix3 | JSON为主要持久化、自定义状态、整行设置入口说明 | SQLite为主要库；当前底部仅齿轮；状态能力继续保留 |
| 1.2 build5 | 新项目、状态管理、SP快照 | 全部继承；不等于GitHub也能合并 |
| 1.2 build6 | 32pt弹窗标题、图片仅附件列表 | 任务/设置头尾48；粘贴图可嵌正文，上传图仍只是附件 |
| navigation-update | 侧栏外凸与概览内凹 | 当前代码保留连续轮廓，禁止独立圆按钮替代 |
| 1.3 scheduling | 一/两/四周、前后翻页；当时未实现start/拖改 | 当前固定14天/日期选择器；显式start、拖动已实现 |
| 1.4 performance | 按需流光、指针隔离、项目甘特、拖动 | 继承；历史资源采样不是其他平台保证 |
| 1.5 GitHub | 私有加密整库、手动与自动 | 继承；不能从早期README末尾的无云同步范围倒推删除功能 |
| 1.6 ui-iteration | 导航合并、快筛、滚动筛选、48头尾、图文、14天 | 最新有效产品变更，优先核对实际代码 |

历史13份原始Markdown保存在history/，只作证据。涉及旧版本的范围说明、测试数量和个人任务计数都不能当作新平台完成状态。

## 3. 已知差异与复刻注意事项

| 编号 | 发现 | 处理要求 |
|---|---|---|
| D01 | 最新顶部分类改变query.category，新建分类仍读scope.category | 原版可能仍默认工作；改善需明确记录 |
| D02 | 日期选择器周日，周/月任务日历周一 | 两套起始规则分别验收 |
| D03 | 今天截止filter含done，历史today scope不含done | 不把两者合并 |
| D04 | 开始+5天是6个日期闭区间 | 不错写成仅5个日期格 |
| D05 | 修改富文本时普通文字也可能产生richDescription | 不能仅按有无图片判断V6 |
| D06 | 附件原图和RTFD图双份保存，移除不联动 | 避免误删和24MiB包超限；改变规则需另立需求 |
| D07 | 月历与甘特anchor/收展是局部状态 | 不承诺重启/重建后保留 |
| D08 | 状态管理没有使用任务/设置共用48头尾 | 记录原版例外，不能声称所有弹窗一致 |
| D09 | GitHub手动也受nextAttempt退避限制 | UI可解释，不能无限重试 |
| D10 | 手动SP客户端没有GitHub专用的显式重定向拒绝策略 | 可作为安全增强，不能误写原版已有 |
| D11 | SP返回对象expiresAt采用下载时+7天，真正校验用密文内期限 | 不用返回值延长真实有效期 |
| D12 | RTFD目前依赖AppKit；其他平台编辑往返未经本次证明 | 单列可用性/兼容性验收 |
| D13 | 源码存在旧scope/move函数但UI无入口 | 不把死入口重新暴露成基线必需 |
| D14 | 本次没有构造新跨平台客户端或新增功能 | 文档是复刻依据，不等于复刻产品已实现 |
