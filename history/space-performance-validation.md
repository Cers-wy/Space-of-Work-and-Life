# Space 1.4.0 build8 · 性能、动画与甘特图编辑验收

日期：2026-10-29（北京时间）。交付：`output/Space.app`。

## 性能排查与修改

1. 原看板把拖拽位置放在AppStore的全局发布状态中，每个指针事件都会通知整个工作台。现将指针发布器、拖拽任务和目标列拆开，只有小型预览随指针移动；列和卡片只在开始/结束拖拽或目标列改变时更新。
2. 原每张卡片各有20Hz内部流光和24Hz外围流光。现在合为一个按需时钟：静止保持玻璃、光边和内部亮光，仅悬停的单张卡片播放流光；拖动、后台和减少动态效果时暂停。
3. 筛选结果与看板状态分组缓存；日期和时间格式器复用；每30秒检查日期时，仅跨日才更新全局状态。甘特图日期网格改为每行一个Canvas，减少逐格视图层级。
4. 原界面偏好调用整库保存，会重写任务及附件。现在只在SQLite事务中更新设置和修订号，保留冲突检测及失败回滚，不覆盖最近一次任务恢复快照。

## 本机资源采样

相同设备、120项任务、4个项目、同等窗口尺寸、暗色看板，按每秒一次采样10秒。新版静止采样时指针放在卡片外；悬停和交互阶段另存原始记录，不作为静止指标。

| 指标 | 1.3.0旧版 | 1.4.0新版 |
| --- | ---: | ---: |
| CPU中位数 | 98.05% | 0.25% |
| CPU采样范围 | 93.3%～100.0% | 0.0%～4.7% |
| RSS内存中位数 | 392.7 MiB | 113.1 MiB |
| RSS采样范围 | 164.3～409.7 MiB | 108.3～119.7 MiB |

CPU中位数下降约99.7%，RSS中位数下降约71.2%。这是本机、该规模、短时静止场景的观测；RSS是进程驻留内存，不代表全部GPU或系统合成器内存，也不是长期泄漏测试或拖拽帧率保证。悬停流光和交互时占用高于静止状态。

原始数据：`work/native-qa/performance/baseline/idle-metrics.json`、`work/native-qa/performance/comparison/idle-pointer-outside.json`。`comparison/idle-metrics.json`及`optimized/idle-metrics.json`含悬停或验收操作阶段，不用于上述静止结论。

## 过渡动画

- 导航与顶部概览展开/收起使用500ms减速曲线，概览箭头随状态旋转。
- 看板、列表、甘特图、日历之间使用淡入和轻微缩放；日历日、周、月之间使用淡入。
- 系统减少动态效果时，关闭导航/概览的布局运动，模式切换使用淡入，卡片流光保持静态。
- 保留现有明暗主题、苹方字体、8pt圆角、玻璃材质和顶部纯图标切换。

## 甘特图规则

- 按已有项目展示“项目→任务”，项目行显示筛选后的任务数和总排期。点击项目行展开/收起，工具栏支持全部展开/收起。无所属项目的任务进入“未分配项目”。
- 拖动排期条中部整体平移，保持时长；拖动左右手柄分别改变开始/截止日期，按自然日吸附，最短为同一天。
- 拖动中仅本行预览，松开且日期实际变化时保存一次。保存沿用原有备份、失败反馈和撤销。日期被外部更改时仍按原有版本冲突规则阻止覆盖。
- 新增可选开始日期，与创建时间独立。任务详情可设置或清除开始、截止日期。拖拽不改变创建时间、状态和完成时间。
- 旧任务仍按原规则推导开始日期。未设置截止日期时默认今天到今天加5天；指定开始日期后，默认结束为开始加5天。仅打开视图不写回；主动拖拽后保存为真实日期，撤销可恢复未设置日期。
- 列表、日历、筛选和详情共用修改后的任务日期。项目总排期随当前筛选和子任务改期更新。
